# Domain documentation

This is a single-context repository. Read the root [`CONTEXT.md`](../../CONTEXT.md) before naming or changing product concepts, and read the relevant decisions in [`docs/adr/`](../adr/) before editing affected code.

Use the glossary's terms in issue titles, agent briefs, tests, and code. If a needed concept is missing, update the glossary when the meaning is settled. If a proposed change conflicts with an ADR, identify that decision in the issue or PR before changing the implementation.

The domain-modeling skill maintains these files as decisions emerge. New ADRs belong in `docs/adr/` with the next available number.
