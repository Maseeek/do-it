# Spec Review: Issue #63 (69d22fe vs e7b284e)

### 1. Missing or Partial Requirements
- **Physical mobile and hosted infrastructure verification**: Spec requires: *"Capture production loading and representative large-history interaction measurements before changing code"* and *"Document measurements, remaining limits, and review findings"*. Verification was conducted exclusively on localhost Chromium using synthetic 4× CPU throttling, responsive viewport emulation, and 50ms mock HTTP delays. Hosted database latency/RLS and physical mobile hardware remain unverified due to infrastructure constraints (connector 403, CLI unauthenticated). This is recorded as an acknowledged boundary in [`docs/performance/2026-10-12/README.md`](file:///home/maciek/Documents/do-it/docs/performance/2026-10-12/README.md).
- **In-flight query cancellation**: Spec requires: *"Fix measured bottlenecks with before/after evidence and preserve observable product behavior."* While bounded 3-wide parallel pagination is implemented in `69d22fe`, aborting in-flight history reads on unmount was intentionally deferred ([`decisions.tsv`](file:///home/maciek/Documents/do-it/docs/performance/2026-10-12/decisions.tsv)). Queries run to completion without `AbortSignal` propagation.

### 2. Scope Creep
- **Apple Health polling removal**: Spec mandates *"...preserving scoring, offline persistence, Duel isolation, wearable behavior, and both appearance modes"* and brief notes: *"Existing assigned issues 32(health)... are out of scope."* Commit `fbc0c76` deleted `pullAppleHealthPending` polling in [`src/lib/store.tsx`](file:///home/maciek/Documents/do-it/src/lib/store.tsx). Although `/api/sync/apple-health` returned HTTP 410 Gone at baseline (confirming no reachable wearable regression), touching health sync touched an assigned out-of-scope domain.
- **Intent preloading**: Spec asked to: *"Make loading, navigation, and Check-ins faster"*. Pre-warming chunk imports on hover/focus (`Header`, `DesktopSidebar`, `BottomNav`) in `f8d7837` represents unrequested proactive preloading, though it preserves deployment guards.

### 3. Implementation Correctness & Preserved Invariants
- **Pagination & history preservation**: Spec mandates: *"...preserving scoring, offline persistence, Duel isolation... and complete history."* Proven correct. `69d22fe` in [`src/lib/duel-sync.ts`](file:///home/maciek/Documents/do-it/src/lib/duel-sync.ts) implements bounded 3-wide batching with contiguous-prefix serial fallback on cap shifts, integer count validation (`Number.isInteger(count)`), and full query ranges. Verified across 14,600 rows ([`duel-loading-cap400.json`](file:///home/maciek/Documents/do-it/docs/performance/2026-10-12/duel-loading-cap400.json): 2385.8ms to 1034.4ms; 170 tests passing).
- **Duel isolation & write barriers**: Overlapping reads during local writes are rejected via `duelQueueRef` ([`src/lib/store.tsx`](file:///home/maciek/Documents/do-it/src/lib/store.tsx)), eliminating optimistic Check-in flicker ([`duel-race.json`](file:///home/maciek/Documents/do-it/docs/performance/2026-10-12/duel-race.json)).
- **Core scoring & persistence**: Duplicate-first streak precedence, rest bridging, and 365-day caps are preserved via `checkInIndex` ([`src/lib/score-calculator.ts`](file:///home/maciek/Documents/do-it/src/lib/score-calculator.ts)). LocalStorage durability remains strictly synchronous.
